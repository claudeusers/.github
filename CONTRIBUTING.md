# Contributing to claudeusers

Thanks for wanting to contribute! This guide covers how to contribute across any repository in the **claudeusers** organization. Individual repos may add their own `CONTRIBUTING.md` with more specific instructions — if one exists in the repo you're working in, follow that instead.

> ⚠️ claudeusers is an **unofficial, community-run** organization for people who use Claude (by Anthropic). We are not affiliated with Anthropic. Please don't submit content that implies official status, uses Anthropic's logos, or misrepresents the relationship.

## Ways to contribute

- **Report a bug or issue** — open an issue using the relevant template
- **Suggest a resource** — propose a prompt, MCP server, guide, or tool for one of our resource repos
- **Improve documentation** — fix typos, clarify instructions, add examples
- **Propose a new repo** — if you think the org needs a new focused repo, open a discussion first before creating one
- **Submit a project** — share something you built with Claude in our showcase repo (once live)

## Before you start

1. Check existing issues and discussions to avoid duplicate work
2. For anything non-trivial, open an issue first to discuss the approach before submitting a large pull request
3. Keep contributions focused — one logical change per pull request

## Submitting a pull request

1. Fork the repository
2. Create a branch: `git checkout -b your-feature-name`
3. Make your changes, with clear commit messages
4. If the repo has tests or a lint step, make sure they pass
5. Open a pull request with:
   - A clear description of what changed and why
   - A link to any related issue
6. A maintainer will review — please be patient, this is a volunteer-run project

## Style guidelines

- Write in clear, plain language — this is a community resource, not a formal spec
- Keep entries in curated lists consistent with the existing format
- Attribute sources and don't copy large blocks of text from elsewhere without permission
- Avoid promotional or spammy submissions — resources should be genuinely useful, not self-promotion

## Code of Conduct

All contributors are expected to follow our [Code of Conduct](./CODE_OF_CONDUCT.md).
