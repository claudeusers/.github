# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in any repository within the claudeusers organization (for example, in a shared script, MCP server config, or tool we publish), please **do not open a public issue**. Public issues could expose the vulnerability before it's fixed.

Instead, please report it privately using one of these methods:

- **GitHub private vulnerability reporting**: if enabled on the affected repo, use the "Report a vulnerability" button under that repo's Security tab
- **Email**: `claudeusers@stanl.ink`

Please include:

- A description of the vulnerability and its potential impact
- Steps to reproduce it
- Any relevant logs, code, or configuration (redact anything sensitive)

## What to expect

- We'll acknowledge your report as soon as we're able — this is a volunteer-run project, so response times may vary
- We'll work with you to understand and confirm the issue
- Once resolved, we'll credit you in the fix (unless you prefer to remain anonymous)

## Scope

This policy covers vulnerabilities in code, configuration, or content published within the claudeusers organization. It does **not** cover vulnerabilities in Claude, Claude Code, or any Anthropic product itself — please report those directly to Anthropic:

- [Anthropic's security disclosure process](https://www.anthropic.com/responsible-disclosure-policy)
